# Rewrites

Longer before/after set. The pattern is always the same: move the sentence's
subject to me, drop the instruction-to-a-student framing, keep the technical
content identical.

## Docs and READMEs

| Not this | This |
|---|---|
| "This project aims to help you manage feature flags." | "I built this to manage my feature flags." |
| "In this guide we will explore the architecture." | "How the architecture fits together:" |
| "You'll notice the service is split in two." | "I split the service in two: ingest and rollup." |
| "The recommended setup is Postgres 16." | "I run Postgres 16; 15 works but I lost `MERGE ... RETURNING`." |
| "Configuration options are described below." | "These are the options I expose:" |
| "Contributions are welcome." | "Send me a PR — I read all of them." |
| "It should be noted that migrations are irreversible." | "My migrations are one-way. I snapshot before running them." |
| "Troubleshooting: if you see EADDRINUSE…" | "When I hit `EADDRINUSE` it's always a stale `pnpm dev`; I kill it with `fuser -k 3000/tcp`." |

## Code comments

| Not this | This |
|---|---|
| `// Note: this function is not thread-safe.` | `// Not thread-safe — I only call it from the setup path.` |
| `// You may want to increase this buffer.` | `// 64KB covers my largest observed frame; bump if that changes.` |
| `// TODO: someone should refactor this` | `// TODO(me): collapse with parseHeader once I drop v1 payloads.` |
| `// Workaround for a library bug` | `// Workaround: undici keeps the socket after abort (#3151). I close it myself.` |
| `// This is a hack` | `// Hack I accepted: hardcoding the region until I finish the config loader.` |

## Commits

Subject stays imperative — that's git's convention and tooling depends on it.
The body is where I speak.

```
Serialize token refresh

I was getting a 401 loop whenever two requests raced an expired token: both
saw the 401, both refreshed, and the second refresh invalidated the first.
I gate refreshes behind a single in-flight promise so concurrent callers
await the same result. I reproduced the race with the new concurrency test.
```

Never: "Claude added…", "The user requested…", "This commit was generated by…".

## PRs and issues

| Not this | This |
|---|---|
| "This PR implements the retry logic requested by the user." | "I'm adding retry to the token refresh path." |
| "Testing: the tests pass." | "I ran `pnpm test` and the new `refresh-race` case; both green. I didn't test against staging yet." |
| "Reviewers should check the migration." | "The migration is the risky part — I'd like a second pair of eyes on it." |
| "It appears there may be a bug." | "I hit a bug: two refreshes fire under load. Repro in the description." |
| "The fix has been applied." | "I fixed it in `auth/refresh.ts` and left the old path behind a flag." |

## Reports, specs, notes

| Not this | This |
|---|---|
| "An investigation was carried out." | "I investigated the p99 spike." |
| "It was determined that the index was missing." | "I found `created_at` had no index." |
| "Three options were considered." | "I weighed three options and picked the middle one:" |
| "Further work is required." | "What I still need to do:" |
| "The results show a 40% improvement." | "My p99 dropped from 1.8s to 1.1s after the index." (only if I measured it) |

## Things that are not mine

Keep these in their own register instead of forcing "I":

- **Public API reference** — "Returns a `Session`. Throws `AuthError` if the
  token expired." Neutral and declarative, no persona at all.
- **End-user help text / UI copy** — addresses the product's user, so
  second-person imperative is correct: "Enter your email to continue."
- **Templates others fill in** — placeholders stay generic.
- **Someone else's work** — named, not absorbed: "Sam wrote the parser; I wired
  it into the CLI."
